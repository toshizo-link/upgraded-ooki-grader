# 個人採点結果のSchool Manager自動配信

先生が答案を確定すると、答案原本と採点結果を結合したPDFを作り、対応する生徒の保護者へ自動配信する機能です。手動の「結果PDFを作成」や一括ZIPのダウンロードとは別に動きます。

実装は `AutomaticResultDeliveryPlanner`、`GuardianDeliveryProcessor`、`PlaywrightSchoolManagerClient` にあります。管理画面に専用の設定タブはなく、技術担当者が設定スクリプトを使用します。

## 今回の実機確認状況（2026年9月19日）

- 配信関連の自動テスト25件、PowerShell構文検査1件が通過しました。自動テストの配信先は代替実装で、School Manager本番への送信試験ではありません。
- 設定スクリプトのOriginヘッダーとIdempotency-Keyの欠落を修正しました。実際のスクリプトをHTTP代替関数で動かし、ドライラン・実送信設定・無効化・ログアウト・WhatIfを確認しました。外部通信はありません。
- インストール済み版は0.9.8です。更新の昇格起動がキャンセルされたため、必要なAPIを利用できません。
- School Manager本番にログインし、生徒番号・氏名の完全一致、保護者だけの宛先、件名・本文入力、通常送信アイコンの有効化まで確認しました。送信は実行していません。
- 実画面との差異3点を修正しました。新規作成は一覧の追加ボタンから開始し、生徒アプリが無効な場合のチェック欄も検証し、文字のない通常送信アイコンを特定します。「送信後に解決済にする」は使用しません。
- 修正後のSchool Managerテスト19件（ネットワークを遮断したEdge画面再現試験3件を含む）と自動配信統合テスト8件が通過しました。実サービスへの自動送信の成功を示すものではありません。
- Computer UseでEdgeを直接操作し、架空PDF（og.pdf、34,731バイト）の添付完了を確認しました。件名・本文は検証用の「test」で、添付名が表示され、通常送信アイコンが有効になりました。送信操作は行っていません。
- 添付のごみ箱を押し、「このファイルを削除しますか？」に「はい」で取消を確認しました。本文・件名を消し、前の「送信先と件名」画面に残った件名も消して一覧に戻りました。試験アカウントは作成していません。先行試験の専用件名は一覧検索0件でしたが、今回の「test」は検索による未作成判定には使っていません。
- 取込済み名簿の旧IDとSchool Managerの正式な生徒番号が一致していません。自動配信前に番号の対応を整える必要があります。今回、実生徒の登録情報は変更していません。
- 以下は実装と運用文書に基づく手順です。外部サービスでの作成・受信・削除が完走した手順として扱わないでください。

### 送信しない画面確認の手順

1. 「メッセージ」の一覧から右下の追加ボタンを押します。宛先選択URLへの直接移動では作成状態が初期化されず、生徒を選んでも進みません。
2. 生徒番号で検索し、番号と氏名が一致する1名だけを選びます。保護者にチェック、生徒は未選択であることを確認します。
3. 未送信試験と分かる件名を入力して「次へ」。表示された生徒・保護者が一致していることを再確認します。
4. クリップから架空の試験PDFを添付し、本文を入力します。実際の答案・成績はこの確認に使いません。添付完了、ファイル名、通常送信アイコンの有効化を確認して止めます。
5. **通常送信アイコンも「送信後に解決済にする」も押しません。** 添付横のごみ箱→削除確認の「はい」で添付を取り消します。本文・件名を消し、戻った「送信先と件名」画面の件名も消して一覧へ戻ります。専用の試験件名を使った場合は、一覧検索でも未作成を確認します。

今回、手順4の本文・PDF添付・送信アイコン有効化と、手順5の取消まで確認しました。添付の取消は画面上で確認しており、サーバー内部の保存領域や監査記録の消去までは確認していません。ブラウザーによる画面確認と、インストールされたOoki Graderからの自動配信は別の試験です。更新版の導入、正式番号の対応、自動処理の通し試験、実送信の受付と保護者側の受信は未確認であり、現状を本番利用可能とは判定していません。

## 1. 導入済み版と設定手段を確認する

1. 専用アップデーターで配信機能を含む版へ更新します。更新前バックアップと更新後のデータ照合は、[ホスト運用ガイド](host-app-setup-and-operations-ja.md#111-更新)に従います。
2. Ooki Graderに管理者としてログインし、`https://ooki-grader.test/api/v1/admin/school-manager/` を開きます。JSONに `configured`、`enabled`、`dryRun` が含まれることを確認します。アプリの通常画面やHTMLが返る場合は、APIが利用できたとは扱いません。
3. このリポジトリの修正済み `installer/Set-OokiGraderSchoolManager.ps1` を使用します。以前に生成された更新媒体の同名スクリプトには今回の修正が含まれない場合があります。

## 2. 試験対象と後片付け方法を先に決める

実送信前に、以下の条件をすべて満たします。

- School Manager上に、新規の試験専用生徒と試験専用保護者を作成できる。
- 生徒番号は未使用で、氏名は試験用と明確に分かるもの。両システムに同じ番号・氏名を登録する。
- 保護者のアプリ・メール・SMS等の受信先は、試験担当者が管理する宛先だけ。実在の生徒・保護者・家族との関連付けはない。
- 新規登録時の招待や通知についても、実在の保護者に届かないことを確認できる。
- 作成する生徒・保護者・メッセージ・添付の削除方法と権限を確認できる。
- Ooki Grader側の試験データを完全に除去する方法が決まっている。現行APIは生徒の無効化のみで、完全削除はできない。完全削除が条件なら、廃棄可能な検証環境で実施し、本番DBへ直接追加しない。

削除できるか不明な状態では、先に登録しません。無効化・退会を完全削除と記録しません。試験用答案は架空の内容だけにし、既存の実生徒の答案を添付しません。

## 3. ドライランで有効化する

技術担当者が、修正済みスクリプトのあるフォルダーでPowerShellを開きます。以下のユーザー名は実際の管理者名と自動化専用名に置き換えます。パスワードは実行後の非表示入力で入力します。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\Set-OokiGraderSchoolManager.ps1 `
  -OokiGraderUrl 'https://ooki-grader.test' `
  -AdminUsername '<Ooki Grader管理者名>' `
  -SchoolManagerUsername '<自動化専用ユーザー名>' `
  -Enable
```

この時点では `-LiveSending` を付けません。出力と設定APIで `configured: true`、`enabled: true`、`dryRun: true` を確認し、`activationStartedAt` を記録します。保存しただけではSchool Managerへの接続確認は完了していません。

パスワードはサービスの保管庫に暗号化されます。ブラウザーにログインできていても、自動化は別のブラウザーを起動するため、自動化用の認証情報の設定が必要です。

## 4. 新しい答案を確定する

1. 試験生徒だけを対象にしたテスト実施を用意します。
2. 試験生徒の架空の答案をPDFで取り込みます。配信候補には、保存中の原本PDFが必要です。
3. 生徒番号と氏名を確認して割り当て、全設問を確認します。
4. ドライラン有効化後に「答案を確定」します。採点途中の答案や有効化前の確定結果は対象外です。
5. 後続処理がPDFを生成・検証し、配信候補を作るのを待ちます。通常、処理がないときは5秒間隔で確認しますが、完了時間を保証するものではありません。

## 5. ドライランの結果を確認する

管理者ブラウザーで次を開きます。

```text
https://ooki-grader.test/api/v1/admin/school-manager/deliveries?limit=200
```

対象の `studentId`、`submissionId`、`kind: result_pdf` を照合します。

| 項目 | 確認する内容 |
| --- | --- |
| `state: pending` | PDF生成待ち。まだ送信されていない |
| `state: ready` | 配信可能な候補。ドライラン後もこの状態のまま |
| `lastDryRunAt` | 値が入っていれば、対象選択と保護者限定の選択を確認済み |
| `sentAt` | ドライランでは空欄 |
| `lastErrorCode` | 空欄であること。値があれば原因を確認 |
| 設定の`lastCredentialTestedAt` | 候補に対する接続確認の成功時刻 |

ドライランはログイン、番号・氏名の照合、保護者限定の選択、件名入力と「次へ」の有効状態までです。添付アップロードと送信は行いません。

同じ番号・氏名が複数ある、保護者がいない、生徒本人も選択される等の場合は停止します。番号・氏名は表記を正規化したうえで一意に照合します。

## 6. 試験専用宛先だけに実送信する

切替前に全配信候補を確認します。実送信設定は生徒1名だけの指定ではなく、待機中の候補全体に適用されます。実生徒の候補が1件でもある、200件を超えて全件を確認できない、他の職員が同時に結果を確定する可能性がある場合は切り替えません。

試験対象だけであることを確認後、同じスクリプトに `-LiveSending` を追加します。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\Set-OokiGraderSchoolManager.ps1 `
  -OokiGraderUrl 'https://ooki-grader.test' `
  -AdminUsername '<Ooki Grader管理者名>' `
  -SchoolManagerUsername '<自動化専用ユーザー名>' `
  -Enable -LiveSending
```

ドライラン済みの `ready` 候補もこの切替後に送信対象になります。別の答案を作り直す必要はありません。

送信内容は、件名「採点結果のお知らせ」、本文「採点結果をお送りします。添付のPDFをご確認ください。」です。添付名は `採点結果_実施日.pdf` 形式です。

## 7. 送信側と受信側の両方を確認する

1. Ooki Graderで対象が `state: sent` となり、`sentAt` が記録されることを確認します。
2. School Managerの送信済みメッセージで、宛先が試験保護者だけ、件名・添付が正しいことを確認します。
3. 試験保護者側で受信し、PDFを開きます。試験生徒の原本と採点結果がそろい、他の生徒の情報が含まれないことを確認します。
4. 追加の処理周期を経ても、同じ確定結果が重複送信されないことを確認します。

`message_send_outcome_unknown` は、送信が成立したか分からない状態です。自動再試行されません。School Manager側で確認するまで、手動の再送もしません。

## 8. 停止し、試験データを削除する

まず `-Enable` と `-LiveSending` を外して同じスクリプトを実行します。

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File .\Set-OokiGraderSchoolManager.ps1 `
  -OokiGraderUrl 'https://ooki-grader.test' `
  -AdminUsername '<Ooki Grader管理者名>' `
  -SchoolManagerUsername '<自動化専用ユーザー名>'
```

`enabled: false` を確認します。未送信の `pending`・`ready`・`failed` 候補は取り消されます。処理中の `sending` は即時取消を保証しないため、送信結果が確定するまで宛先を削除しません。

その後、事前に確認したSchool Managerの削除機能で試験メッセージ・添付・試験保護者・試験生徒を削除します。検索で残存と関連付けがないことを確認します。廃棄可能なOoki Grader検証環境も撤去し、テスト専用認証情報を残しません。監査記録など製品上削除できないものがあれば、残る内容を正確に記録します。

## 9. 本番運用へ移るとき

今回の依頼は試験専用宛先での確認です。本番の保護者向け自動配信は有効化しません。本番移行時は、正式な番号の対応表、保護者限定選択、送信先、運用担当者、訂正・停止時の扱いを別途確認します。

採点結果を送信前に再開すると未送信候補は取り消されます。送信済みPDFは自動回収されません。クラス合否表の1日1回制限は個人採点結果と別の規則です。
