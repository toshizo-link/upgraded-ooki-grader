# Ooki Grader 0.9.10 から 0.9.14 への更新ガイド

対象: Windows ホスト PC の管理者・設置担当者  
作成日: 2026年9月20日  
更新元: 0.9.10  
更新先: 0.9.14

## このガイドの目的

既に Ooki Grader 0.9.10 が動作している Windows ホスト PC を、配布された更新メディアを使って 0.9.14 へ更新します。0.9.11、0.9.12、0.9.13 を個別に適用する必要はありません。更新ツールが、現在のデータベースへ必要な変更を順番に適用します。

本書は、学校内で管理されているポータブル版インストールを対象とします。新規インストールには使用しません。

## 重要な原則

- 採点、答案取込、帳票出力をすべて止めてから更新します。
- 更新前24時間以内に作成された、完全検証済みの暗号化バックアップを使用します。
- 配布された更新フォルダーは、ファイルを追加・削除・編集せず、そのまま使用します。
- 更新中は PC の電源を切らず、更新画面を閉じません。
- エラー時に DLL、データベース、操作マーカー、Windows サービスを手作業で変更しません。
- `UPDATE WITHOUT BACKUP` と表示された場合は入力せず、その場で中止して保守担当者へ連絡します。

## 1. 更新前に確認する

### 1.1 利用者へ停止を案内する

1. 先生方へ更新時間を案内します。
2. 答案のアップロード、氏名確認、採点、確定、PDF出力を終了してもらいます。
3. 受付中のテストや処理中の答案がないことを確認します。
4. ブラウザーを閉じてもらいます。

### 1.2 システム状態を確認する

管理者アカウントでログインし、`管理` → `システム状態` を開きます。

- ホストが接続中であること。
- データベースや保存領域に重大な警告がないこと。
- 処理中のバックグラウンドジョブがないこと。
- AI を利用している場合は、更新前の接続状態を記録すること。

警告や処理中のジョブがある場合は、更新を始めません。

### 1.3 バックアップを作成して完全検証する

1. `管理` → `システム状態` のバックアップ欄で、保存先と暗号化設定を確認します。
2. 更新直前のバックアップを作成します。
3. 完全検証が成功したことを確認します。
4. バックアップの完了日時が24時間以内であることを確認します。
5. バックアップが 0.9.10 のデータから作成されていることを確認します。

`復元計画を確認` だけではバックアップの作成・復元は行われません。

## 2. 更新メディアを準備する

配布元から受け取った次のフォルダーを、ホスト PC のローカルディスクへフォルダーごとコピーします。

`OokiGrader-0.9.14-Windows-Host-Update`

フォルダー内に次の7ファイルがあることを確認します。

- `00-README-ja.txt`
- `01-Update-OokiGrader-Host.cmd`
- `OokiGrader-0.9.14-win-x64.zip`
- `OokiGrader-0.9.14-win-x64.zip.sha256`
- `Update-OokiGrader-Host.ps1`
- `checksums.txt`
- `media-inventory.json`

アプリ本体ZIPが **306,520,713 bytes** で、SHA-256が次と一致することを配布元で確認します。

`28a7b0ef33c61a400c279b2d42b3af533cb734b0081cbd9f27858f5a0939e821`

数百bytes程度しかないZIPはGit LFSの未取得ポインターであり、更新には使用できません。ZIPを手動で展開せず、ファイル名を変更せず、`checksums.txt` と `media-inventory.json` も編集しません。

## 3. アップデーターを開始する

1. `OokiGrader-0.9.14-Windows-Host-Update` フォルダーを開きます。
2. `01-Update-OokiGrader-Host.cmd` を右クリックします。
3. `管理者として実行` を選びます。
4. Windows のユーザーアカウント制御が表示されたら、発行元と実行ファイル名を確認して許可します。
5. 黒い更新画面が開いたら、SHA-256 検査と展開が終わるまで待ちます。

更新ツールは、ZIP、内部ファイル、現在のインストール、データベース状態、最新のバックアップを自動検査します。

## 4. 表示内容を照合して更新する

確認画面で、少なくとも次の内容を照合します。

| 表示項目 | 正しい内容 |
|---|---|
| Current version | `0.9.10` |
| New version | `0.9.14` |
| Data | `C:\ProgramData\OokiGrader\Data` |
| Backup | 最新の検証済みバックアップの相対パス |
| Backup completed | 更新開始前24時間以内 |
| Safety | `verified backup and prior version retained` |

すべて正しい場合だけ、半角大文字で `UPDATE` と入力して Enter キーを押します。

`UPDATE WITHOUT BACKUP` を求められた場合は、何も入力せず画面を閉じ、保守担当者へ連絡します。本書ではバックアップなしの更新を実施しません。

## 5. 完了まで待つ

更新中は次の処理が自動で行われます。

1. Ooki Grader サービスを停止する。
2. オフラインのメンテナンス状態へ移行する。
3. 0.9.14 のアプリケーションを設置する。
4. データベースを更新する。
5. サービスを起動する。
6. データベース、保存領域、HTTPS、サービス状態を検査する。
7. 旧アプリケーション版を復旧用に保持する。

`Ooki Grader host update completed successfully.` と表示されるまで、PCをシャットダウンせず、更新画面を閉じません。

完了後、表示された診断結果と診断ログの場所を記録します。

- `C:\OokiGrader-Setup\logs\host-update-0.9.14-<実行ID>.log`
- `C:\OokiGrader-Setup\logs\host-update-0.9.14-<実行ID>.result.json`

## 6. 更新後の画面確認

### 6.1 ログインとダッシュボード

1. 通常の学校内URLを開きます。
2. 管理者アカウントでログインします。
3. 右上の表示名が自分であることを確認します。
4. `ホスト接続中` と表示されることを確認します。
5. ダッシュボードがエラーなく表示されることを確認します。

### 6.2 既存データ

次の項目を閲覧し、更新前の内容が残っていることを確認します。

- 生徒: 既存の生徒番号、氏名、クラス。
- テストひな形: 公開済みひな形、問題、正解、配点。
- テスト実施: 直近の実施と答案の状態。
- 帳票: 確定済み結果、点数、訂正履歴。
- 結果PDF: 更新前から存在する1件を開き、表示できること。

確認のために既存データを編集・再確定しません。

### 6.3 管理機能

`管理` → `システム状態` を開きます。

- 重大な警告がないこと。
- バックアップ情報が表示されること。
- AIを利用している場合は、接続状態が更新前と一致すること。
- School Manager連携を使用する場合は、自動配信の有効・無効が意図どおりであること。

School Manager の本番送信は、別途、管理されたダミーアカウントで確認してから有効化します。更新確認だけを目的に実在の保護者へ送信しません。

## 7. 利用を再開する

1. 更新完了時刻と担当者名を記録します。
2. 診断結果と診断ログを保管します。
3. 先生へ更新完了を連絡します。
4. 最初の答案取込と採点は、通常より慎重に状態を確認します。
5. 問題がなければ通常運用へ戻します。

## 8. エラーが表示された場合

1. エラー文を写真またはスクリーンショットで記録します。
2. 更新画面に表示されたログの場所を記録します。
3. 同じ更新を何度も実行しません。
4. DLL、データベース、`migration.in-progress` などの操作マーカーを変更しません。
5. Windows サービスを手作業で旧版へ向け直しません。
6. ホスト PC の電源は切らず、保守担当者へ連絡します。

アップデーターがデータベース変更前に停止した場合は、旧版が自動復旧されます。データベース変更後の復旧判断は、検証済みバックアップと診断ログを使って保守担当者が行います。

### 保守担当者へ渡すもの

- 更新元: 0.9.10
- 更新先: 0.9.14
- 実行日時と担当者名
- 画面に表示されたエラー全文
- 最新の `host-update-0.9.14-<実行ID>.log`
- 同じ実行IDの `.result.json`
- 更新後にブラウザーで確認できた項目・できなかった項目
