# School Manager 保護者配信（第四段階）実装計画

## 目的

教師が採点結果を確定した後、答案原本と採点結果を連結した PDF を対象生徒の保護者へ送る。合否表が更新されたときは、対象生徒と同じクラスだけを含む匿名化 PDF を作り、各保護者へ一日一回を上限として送る。

## 安全境界

- 本番の School Manager では読み取り確認とドライランだけを行う。実送信テストは、専用のダミー生徒・ダミー保護者が確認できた後に行う。
- School Manager の認証情報はソース、設定 JSON、更新メディア、ログへ保存しない。Ooki Grader の管理者 API を通して、サービス実行アカウントの DPAPI 保管庫へ保存する。
- 生徒は Ooki Grader の生徒番号と氏名の完全一致で照合する。0 件、複数件、保護者 0 件、表示内容の不一致では送信しない。
- 合否表は同じクラスの行だけを残す。氏名列は除去し、本人以外の生徒 ID は `同級生01` のような連番へ置換する。対象本人は `本人` と表示する。
- 「1日に2回以上送信しない」は、安全側に一日一回を上限として実装する。同日中の更新は最新内容へまとめ、翌日へ繰り越す。
- 送信記録とエラーコードを監査可能に保存し、再起動や再試行で重複送信しない。

## 実装手順

1. 合否表の読み取り・匿名化モデル・PDF描画と単体テストを追加する。
2. 保護者配信設定、合否表取込、配信キューの永続化モデルと移行を追加する。
3. 採点確定結果の自動PDF生成、再開時の未送信取消、合否表更新の検出と一日一回制御を実装する。
4. Playwright と Edge を使う School Manager クライアントを追加する。対象照合、保護者限定、添付上限、最終確認の検査に失敗した場合は送信しない。
5. 管理者用の設定・状態確認 API と、資格情報を安全に登録する技術者スクリプトを追加する。既定は無効かつドライランとする。
6. 更新メディアへスクリプトを含め、0.9.14 の更新メディアを作成する。
7. 単体・統合・インストーラ検査を実行し、本番サイトでは送信を伴わないドライランだけを確認する。
